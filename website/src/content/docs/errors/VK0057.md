title: "no partition covers the next message id"
slug: errors/VK0057
kind: "event"
level: "warn"
consequence: "degraded but self-healing, or a durable data consequence; an operator should learn of it eventually"
---

An insert was routed to a message_log partition that did not exist, and
the write path created it. Nothing is lost -- the attempt reruns on the
retry schedule ([VK0056](/errors/VK0056)) -- but that insert paid the
creation latency instead of the create-ahead pass.

Once at a boundary means create-ahead did not run: no consumer is
running the topic's upkeep. Every boundary under load means bursts are
outrunning the 80% and 95% triggers: raise `PartitionSize`.
