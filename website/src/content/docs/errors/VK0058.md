---
title: "schedule target topic keeps no success rows"
slug: errors/VK0058
kind: "event"
level: "warn"
consequence: "ScheduleStatus counts no successes for it; set DeliveryLogMode all on the topic to count them"
---

`Scheduler.Register` found the target topic's `DeliveryLogMode` set to
`failures` (the default) or `off`. `ScheduleStatus` and `ScheduleMessages`
read the target topic's `delivery_log` by the schedule's message key, so a
success that writes no row is a success the status never sees: `succeeded`
stays 0 and every run reads as pending or failed.

The schedule registers and produces regardless - the mode only decides
what the status verbs can report.

To count successes, register the target topic with
`DeliveryLogMode: topic.DeliveryLogModeAll`. That writes one row per
success on that topic, for every message on it, not only the schedule's.
