---
title: "could not insert the message, no partition covered its id"
slug: errors/VK0056
kind: "error"
recovery: "transient"
consequence: "an unchanged retry can succeed; retry machinery retries on its backoff schedule"
---

The insert was routed to a message_log partition that did not exist yet.
The producer has already created it -- the partition covering the id
sequence's next value -- and the attempt reruns on the retry schedule. A batch
can straddle a partition boundary, so one rerun may meet a second
missing partition; each one is created the same way.

Seen at exhaustion, ids are outrunning partition creation: raise
`PartitionSize` or the retry policy's `MaxRetries`.
