---
title: "topic config replaced"
slug: errors/VK0061
kind: "event"
level: "warn"
consequence: "the newest declaration wins; if this is unexpected or repeats on every restart, two services declare this topic with different configs and overwrite each other"
---

`Client.RegisterTopic` found the topic already registered and the
declared config differed from the stored row. The row keeps the newest
declaration; each changed field rides the line as its own attribute
carrying `old -> new` (`retention_ttl`, `allow_drop_past_committed`,
`idempotency_key_ttl`, `delivery_log_mode`), and the full snapshot -
with `declared_by` and `declared_at` - lands in `topic_config_log`.
`PartitionSize` is not part of this: a differing one is refused with
[VK0004](/errors/VK0004/) and nothing is written.

One line is a config change landing. The same line on every deploy
means two services both declare the topic with different configs and
overwrite each other on restart - a topic's config wants exactly one
declaring service, and nothing in the library enforces that beyond this
line. The diagnose query lists the declarations the topic has received,
with who declared each:

```
vulkan explain VK0061
```
