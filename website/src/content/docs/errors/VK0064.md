---
title: "the connecting role cannot create the schema"
slug: errors/VK0064
kind: "error"
recovery: "permanent"
consequence: "an unchanged retry cannot succeed; retry machinery stops immediately"
fix: "grant it CREATE on the database, or create schema {schema} yourself and grant the role USAGE and CREATE on it"
---

Vulkan keeps its tables in a schema of their own, `vulkan` by default, so
the shared control-plane tables and the ten tables every topic creates
never land beside your own. `RegisterSystem` creates that schema before
it creates anything else, and Postgres refused: the role in the
connection string has no `CREATE` privilege on the database.

Nothing was created. No schema, no tables, no system row.

Either grant the role the privilege:

```sql
GRANT CREATE ON DATABASE orders_db TO app_user;
```

Or create the schema yourself - useful when the application role is
deliberately not allowed to create schemas - and let the role work
inside it:

```sql
CREATE SCHEMA vulkan;
GRANT USAGE, CREATE ON SCHEMA vulkan TO app_user;
```

`CREATE` on the schema is still needed after the first path too: Vulkan
creates a table per topic, and per topic partition, for as long as the
system runs.

## Choosing a different schema

`PostgresConnectionConfig.Schema` moves every table somewhere else. One
schema holds exactly one Vulkan installation, so two schemas in the same
database are two independent systems that share nothing.

```go
ds, err := datastore.NewPostgresDatastore(ctx, "app_user", "localhost", "orders_db",
	&datastore.PostgresConnectionConfig{
		Pass:   os.Getenv("PGPASSWORD"),
		Schema: "vulkan_staging",
	})
if err != nil {
	return err
}
```

The name has to be a lowercase unquoted identifier - it reaches
`CREATE SCHEMA` and the connection's `search_path` as written, so
anything else is rejected by `Validate` rather than quoted.
